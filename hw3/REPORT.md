# Отчёт по ДЗ 3

## Набор данных

Используется текущий снимок вакансий восьми российских регионов из
официального API «Работа России». Снимок не выдаётся за исторический архив.
Строка однозначно определяется парой `(snapshot_date, vacancy_id)`.

Перед сохранением удаляются контакты, точные адреса и свободные тексты. В
PostgreSQL попадает плоский аналитический набор из 20 полей.

## Сравниваемые варианты

1. `vacancies_base` — таблица без дополнительного индекса.
2. `vacancies_indexed` — B-tree
   `(region_code, sphere_name, creation_date)`.
3. `vacancies_partitioned` — range partitioning по `snapshot_date`
   с секцией 2026 года и default-секцией.

Все три таблицы загружаются из одного CSV. Их полное равенство проверяется
`EXCEPT ALL` в обе стороны.

## Методика измерения

На каждой таблице выполняется одинаковый отчёт по профессиональным сферам
Башкортостана. PostgreSQL сначала получает один прогрев, затем пять
измеряемых запусков `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`.
В отчёт попадают серверный `Execution Time`, медиана повторов и буферы.

Численные результаты формируются запуском `make benchmark` и сохраняются в
`evidence/optimization/summary.json`; планы лежат рядом в каталоге
`plans/`. На снимке из 51 210 вакансий отчёт вернул 34 сферы. Медиана пяти
запусков: baseline — 5,805 мс, indexed — 3,644 мс, partitioned — 5,150 мс.
Индекс дал самый заметный выигрыш; секционирование почти не ускорило запрос,
потому что весь текущий снимок находится в одной секции 2026 года.

SHA-256 результата всех трёх вариантов совпал:
`bf362a65b75d65f042c326e4c44a1cbf2473797f37371ada0121bcfb72966b30`.

## Репликация

Patroni и etcd используются только для учебного эксперимента. Скрипт записывает
маркер на primary, ждёт его на replica, подтверждает ошибку записи
`read-only transaction`, выполняет switchover и повторно проверяет
репликацию. Результат сохраняется в `evidence/replication.json`.

## Backup и restore

Создаётся custom backup `pg_dump -Fc`, затем отдельная база
`hw3_restore`. Сравниваются таблицы, индексы, constraints, секции, все
колонки, числа строк, ключи, контрольный срез и результат benchmark-запроса.
Evidence считается совместимым только с контрактом
`hw3-vacancy-mart-v1`.

Финальный backup имеет размер 16 068 074 байта. В исходной и восстановленной
базах по 51 210 строк и уникальных ключей в каждой benchmark-таблице,
`invalid_rows = 0`, все проверки равенства прошли.

## MVCC

Две сессии `READ COMMITTED` показывают:

- незакоммиченное изменение первой сессии не видно второй;
- после commit новое значение становится видно;
- конкурентный update ждёт row lock;
- после rollback владельца ожидающая сессия продолжает работу.

Результат сохраняется в `evidence/mvcc.json`.
