# ДЗ 2: DWH вакансий «Работы России»

## Идея

Потребитель — аналитик региональной службы занятости. Витрина показывает
текущий спрос на работников по регионам и профессиональным сферам.

Источник — официальный API
[«Работа России»](https://opendata.trudvsem.ru/api/v1/vacancies).
Это API текущих вакансий, а не архив. Поэтому каждый запуск создаёт снимок на
свою дату, а ключ факта — `snapshot_date + vacancy_id`.

Для учебного проекта выбраны восемь небольших субъектов, по одному из каждого
федерального округа: Тульская, Калининградская, Волгоградская, Курганская и
Новосибирская области, Дагестан, Башкортостан и Хабаровский край. Всего
получается примерно 51 тысяча вакансий.

## Почему загрузка простая

API отдаёт не больше 10 000 строк для одного фильтра. В каждом выбранном
регионе меньше этого лимита, поэтому downloader просто читает страницы по 100
строк в 8 потоков. В проекте нет рекурсивных временных окон, checkpoint,
адаптивной параллельности и SCD2.

Результат сохраняется в
`data/source/trudvsem_vacancies_YYYY-MM-DD.jsonl.gz`. Перед записью остаются
только аналитические поля. Контакты, ФИО, телефоны, email, адреса и свободные
тексты не сохраняются.

Обычное время скачивания — около 10–15 минут; весь pipeline должен уложиться
примерно в 20 минут при нормальной работе API.

## Модель

```text
raw.trudvsem_vacancies
          ↓
stg_trudvsem_vacancies
          ↓
dim_date ────┐
dim_region ──┼── fct_vacancies ── mart_regional_sphere_demand
dim_sphere ──┘
```

Витрина имеет гранулярность
`snapshot_date × region × professional sphere` и содержит:

- количество вакансий и рабочих мест;
- среднюю нижнюю и верхнюю границу зарплаты в рублях;
- долю вакансий без опыта.

Повторная загрузка той же даты заменяет её raw-снимок и не создаёт дубли.

В raw сохраняются исходные значения. В staging выполняются только две простые
нормализации, найденные на реальной выгрузке: перепутанные границы зарплаты
ставятся по возрастанию, а строка стажа вида `от 0` превращается в число `0`.
Нулевое или отсутствующее число рабочих мест считается одним местом.

## Pipeline

Airflow DAG `trudvsem_vacancy_elt` содержит четыре задачи:

```text
download → load_raw → dbt_build → publish
```

`dbt build` строит модели и запускает проверки. Только после него
`publish.py` пересоздаёт
`published.mart_regional_sphere_demand` в одной транзакции.

## Запуск

Нужны Python 3.11 и PostgreSQL 14.

```bash
make setup
make pipeline
make diagnostics
```

Отдельные шаги:

```bash
make download
make load
make dbt-build
make publish
make unit
make test
make airflow-test
```

`make download` всегда скачивает текущее состояние API и поэтому разрешает
только сегодняшнюю дату. Чтобы воспроизвести уже сохранённый снимок без нового
скачивания:

```bash
make replay SNAPSHOT_DATE=2026-10-06
```

Аналитические примеры находятся в `sql/analysis.sql`.
